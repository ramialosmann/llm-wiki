# LLM wiki conventions (v2)

Karpathy's LLM-wiki pattern (https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f), kept in step with
git and tuned to save tokens. The human curates sources and asks questions; Claude keeps the pages true. A wiki's
own `CLAUDE.md` (its schema) takes precedence over this file.

## What a page is for

Write only what the code can't tell an agent. Studies of agent context files found that overviews and
restatements of the code add cost without helping (ETH, arXiv:2602.11988); the code map (`code/<repo>-map.md`,
regenerated per commit) already answers *where* things are.

- **Keep:** decisions with the reason and the rejected options; rules and invariants that aren't obvious from the
  code; traps and gotchas; commands and recipes (run, test, deploy, seed); external systems (servers, env,
  third parties); open questions.
- **Don't write:** what a module does, API or endpoint lists, file inventories, pasted code, changelog sections.
- Say what is true **now**. When a fact changes, rewrite it in place; history lives in git and `log.md`. No dated
  headings like `## Feature (2026-10-14)`.
- Point at code by path, `repo:path/to/file.ts`. Add `paths:` (globs) to a page that owns an area, so sync maps
  changed files to it.

## Layers

| Layer | Where | Who writes |
|---|---|---|
| Raw sources | `raw/` (+ the tracked repos) | Human adds; never edited after landing |
| Wiki | every other `.md` | Claude |
| Generated | `code/<repo>-map.md` | `wiki-map` only (never edit; git-ignored in the vault) |
| Schema | `CLAUDE.md` in the wiki root | Human + Claude |

## Required files

- `index.md`: the page list sits between `<!-- wiki-index:start -->` and `<!-- wiki-index:end -->` and is
  regenerated by `wiki-index` from each page's `summary:` (prose outside the markers is kept).
- `log.md`: append-only, newest at the bottom, written only by `wiki-finish`. Headings
  `## [YYYY-MM-DD] <op> | <title>`; `grep '^## \[' log.md | tail` for history. Never read it whole.
- `state/<repo>.md`: frontmatter `synced:` maps branch → short sha of the last commit folded in (only
  `wiki-finish --bump` moves it). Body: **Now** (≤3 lines), **Next**, **Blocked**. The session brief injects it.

## Pages

- One topic per page; kebab-case filenames unique across the wiki (Obsidian resolves `[[name]]` by basename).
- Frontmatter: `title`, `type`, `summary` (one line, quoted; feeds the index and the session brief), `tags`,
  `updated`, `sources`, optional `paths` (list of globs), `verified: <repo>@<sha>` on pages that describe code.
- Types: `overview` (for humans; never injected), `state`, `component`, `concept`, `decision`, `plan`, `howto`,
  `source`, `discussion`, `thesis`, `index`, `log`, `code-map` (generated).
- Open with a `> [!abstract] TL;DR` callout; link generously; keep contradictions visible under
  `> [!warning] Conflict` until resolved. A superseded decision gets `status: superseded` and a link to its
  replacement.
- Aim under ~6 KB per page; split by topic rather than grow.

## Habits

Keep `index.md`, `log.md` and `synced:` true through the commands, never edit `raw/` or `code/`, and look things
up with `wiki-find` before grepping. Nothing here overrides session or auto-mode instructions.
